# ADR 005 — Phase 2 typed workflow execution

2026-10-26 JST. Builds on ADR 002–004; does not replace Workflow First. Implementation branch `feat/workflow-phase-2`, investigated clean main `15b51bfabce277ff040559a66616c0f255011ab6`. Fetched current main before editing; no AGENTS.md was present in the repository or ancestors. Node 24.19.0 / npm 11.9.0. Dependencies and lockfile unchanged.

## Architecture and graph contract

`domain/workflow/execution.ts` defines run/node/attempt, immutable values, resolver and repository interfaces. `services/workflow/runner.ts` depends on these contracts and a registry, with no React, DOM, auth or animation requirement. Built-in image handlers dynamically import the existing browser renderer. The scheduler is deliberately serial (one image **or** lightweight node), below the proposed 1/2 concurrency limits. No performance evidence justifies parallel full-resolution decoding yet. Registry ports, validation and handlers are separate from transport and view state; queue/backpressure/item identifiers can be added later without making animation completion an execution condition.

Validation uses the existing strict v1/v2 parsers for versions, node configs, duplicate IDs, limits (200 nodes/1,000 edges/5MiB serialized graph), exact port types, single-input cardinality and cycles. Registry checks supported typeVersion and required inputs. Empty source, missing applied editor revision and save/post are preflight errors. Unknown/corrupt stored graphs are never converted or overwritten. `save@1` and `post@1` remain readable configuration nodes and always fail execution as `UNSUPPORTED_NODE`, before any cache lookup. No network handler, arbitrary JavaScript or save side effect exists.

A stable Kahn sort uses lexicographic node IDs for ties. Collection pack has explicit first/second image ports; order optionally reverses a copy, item uses a zero-based index. Image collections preserve references and order, not copied pixels. Text and number are typed scalar values; generic text/file/audio/video collection editing is not claimed. Scalar image references may fan out freely. New number/adjust/crop/resize/collection nodes are additive **Workspace v2** definitions with typeVersion 1; Workflow v1's schema is unchanged. No old nodes or documents are rewritten. Legacy image@1 resize preserves aspect ratio using width; crop is a centered square of that width. Explicit new resize fits within width/height with transparent padding; crop uses cover. Adjust shares Studio color filters with values 0–2.

At start, graph/config, source hashes, applied revision/page IDs, renderer version, full font-manifest hash and output spec are pinned. Snapshots are cloned and frozen; UI events receive clones. Graph edits cannot modify active computation. v1 sources resolve in the legacy DB and v2 sources in Workspace, with no fallback between meanings. Applied image-edit v1 inputs remain frozen: connected input hash mismatch is an actionable `EDIT_INPUT_CHANGED`, never a silent layer substitution. Generate upstream first, consume its result in the editor, then explicitly apply before running that editor node. Ancestor computational identity permits layout/downstream edits but rejects stale upstream results.

## Persistence decision and atomic adoption

Chosen DB: separate `axfluxo-execution` **v1** with runs, attempts, cache, outputs. Existing `axfluxo`, `axfluxo-workflow` and `axfluxo-workspace` versions/stores are unchanged. Workspace stores documents/recovery/editor revisions/originals/manual artifacts; execution stores bounded per-operation transient results, immutable result bytes, snapshots and attempt history. This avoids upgrading Workspace v1 and causing `VersionError` in the released client, and does not prematurely create `axfluxo-library`. Source and editor references point to existing immutable data; they are not eagerly duplicated into execution storage.

A node adoption transaction atomically stores output bytes, cache, attempt and updated run. Only transaction completion means durable success. Abort/quota/open/blocked failures cannot publish partial results. All connections close in finally and onversionchange; blocked opens reject and close any late successful connection. A newer unsupported execution DB version returns a safe VersionError message, without deletion. Initial creation uses onupgradeneeded; there is no document migration, no in-progress migration marker, no second display or forced conversion. Existing explicit copy migrations and backup formats remain unchanged and are covered by their regression tests.

The editor-input adapter materializes **only an output consumed by the unchanged v2 editor** into Workspace assets under its immutable output ID/hash. This intentional copy is needed for v2 AssetRef, revision, recovery and ZIP portability. Repeated consumption is idempotent, never overwrites bytes, and verifies the hash. Execution remains the owner of its intermediate result; Workspace owns the editor's fixed copy. These IDs/hashes preserve the same asset meaning. There is no parallel library asset store.

History queries use IDB indexes and show the most recent 100 runs; older history is retained. No automatic history deletion is added. Persisted run/attempt/cache schemas reject corrupt data; errors do not erase records. Cache eviction scans histories by cursor, pins every output referenced by a run or its snapshot, clears cache pointers and removes only unpinned execution bytes atomically. Histories retain successful outputs from failed/cancelled runs when already committed; cancelled nodes expose no provisional result. Run/attempt history and unconsumed intermediates are local and **not included in Workspace ZIP**. Consumed editor inputs are included through the existing backup path. A dedicated execution archive/retention UI is future work.

## State, cancellation and recovery

Run, NodeRun and Attempt have distinct identities. Normal transitions are queued → running → succeeded/failed/cancelled; dependencies without successful output become blocked, and abandoned queued/running records become interrupted. Attempts are created only when starting work. Stop policy cancels not-yet-started independent work; continue policy runs independent branches. Both block descendants of failures, with no fabricated outputs. Retry creates a new run and attempt IDs, links retryOf, and increments attempt number; prior history remains immutable.

The browser host holds the `axfluxo-execution` Web Lock through snapshot preparation and execution. A second tab cannot start/evict cache or mark a live run interrupted. Recovery acquires that lock only if available, marks abandoned states/attempts interrupted, and never replays work. Browsers without Web Locks report unsupported safe execution; editing/storage remain available. Runner/repository interfaces remain usable without browser locks for a future host.

AbortSignal is checked before work, after decoding/encoding/hashing, and during the adoption transaction. Cancellation starts no new node and cannot turn an unabortable completed encode into a succeeded node. Stage/Canvas export resources use existing finally cleanup; no new permanent stage or bitmap cache exists. Preview object URLs revoke on close/unmount. pagehide/unmount/workspace navigation aborts local work. Background visibility alone does not restart work: a suspended live tab resumes its own promise; terminated/reloaded work becomes interrupted when its lock is released. No claim of physical iOS background reliability is made.

## Cache and memory

Cache key: canonical node type/typeVersion/config, typed inputs (including immutable hash/reference/version), pinned source/revision, renderer version, font manifest hash and PNG output spec. Object property order is irrelevant; collection order is significant. Missing/corrupt cached references cause recomputation. All supported handlers are pure computations. Unsupported future side effects cannot be made successful by cache/retry; formal save needs an operation/idempotency contract in Phase 3.

Input bytes ≤20MiB, ≤24MP, side ≤8192; generated render ≤8.5MP and side ≤4096 (min 64). MIME/signature/header dimensions/decoder dimensions/hash and animation rejection precede acceptance. file/audio/video never coerce to image. Sources are pinned sequentially; each operation decodes sequentially through the shared renderer, and outputs spill to IndexedDB at each node. The graph and run's value table hold metadata/references, not Blob/base64/object URLs. Hashing still requires an ArrayBuffer (up to 20MiB); exact peak heap/GPU use is browser-dependent and not claimed as a measured hard bound. History is disk-retained; quota errors are surfaced. Multiple user-opened previews and pre-existing multilayer editor rendering remain possible memory costs.

## Future reference contract and rollback

The existing `{assetId,hash}` stays unchanged. Tagged workspace/legacy/execution/library references disambiguate stores. A library reference requires libraryId/fileId/**versionId**/kind/hash; lookup never follows latest. A typed injected library lookup is a contract/adapter, not an implemented material-library UI/DB. LibraryDescriptor carries MIME, size, dimensions and application metadata outside graph bytes. Audio/video may be described, not edited. Future SaveResult is a committed reference or ordered references, but no handler currently returns a fake save.

Phase 3 must supply a real immutable version store, reference retention/backup/quotas, transactional operation/idempotency and explicit UI/import contracts before save can run. It must preserve existing AssetRef adapters. Phase 6 can replace scheduling with bounded queues/backpressure and item IDs while consuming the same typed values, stable order and onChange snapshots; no belts/hoppers/transport animation are implemented.

Rollback execution UI with `NEXT_PUBLIC_WORKFLOW_RUNNER_ENABLED=false` and rebuild. v2 documents/new nodes/references still validate and are retained; the flag disables execution, not storage. Revert this feature to return to main: original v1/v2 documents remain readable; documents containing new node types are retained on disk but the older strict client refuses them rather than rewriting them. Re-enable the feature to read them. Existing Workflow First/legacy flags are unchanged. Do not delete any DB. No migration rollback is required. Merge/deploy are separate and were not performed.
