# Workflow First — iPhone Safari 実機受け入れ

更新: 2026-10-25 JST。WFR-1〜5実装済み、WFR-6の実装側検証と実機受入を分離する。
**実機結果は未取得。以下は実施手順であり、成功記録ではない。**
自動検証の記録は [WFR-6結果](workflow-first-wfr6-results.md) を参照。

## 準備・記録

- PR #5のレビュー対象SHAと一致する、承認済みHTTPS検証URLを用意する。
  Merge前の公開本番サイトは旧版の可能性があり、PRの実機検証に代用しない。
  Actionsの静的artifactはダウンロード用で、そのリンク自体は動作するWebサイトではない。
  ローカル配信の場合もiPhoneが信頼するHTTPSが必要。LANの平文HTTPでは
  crypto等のSecure Context要件を満たさない。検証のために本番設定や認証設定を変えない。
- 端末機種、iOSの正確な版、Safariの版/ビルド（確認できない場合はiOS版と不明を記載）、
  SHA、検証URL、rootか `/axfluxo/`、日時、縦横、通常/プライベート表示を記録する。
- 既存作品は旧ZIP/新Workflow ZIPを端末の「ファイル」へ保存してから実施する。
  普段の作品ではなく「WFR6受入A/B」という試験作品を使う。サイトデータを削除しない。
- 64×48等の小さいJPEGとPNG、写真ライブラリの通常写真を用意する。
  HEICしか選べない場合はJPEG/PNGへ変換した試験素材も用意し、未対応形式と区別する。
- 失敗時は操作、表示、再現回数、画像形式/寸法/容量、画面録画、影響作品を記録する。
  保存失敗中は再読み込みせず、画面を保ち、可能なら別コピー/バックアップを先に行う。

## 結果欄・停止条件

各番号に「成功 / 失敗 / 未実施」、実測時間、再現条件を記入する。
Chromium mobile、Playwright WebKit、実機Safariの結果欄を分ける。
メモリは3回以上の開閉/出力取消後の推移をSafari Web Inspector等で測定できる場合だけ
実測値として記録し、DOM上のCanvas解放を端末全体のメモリ解放と同一視しない。

旧データ消失、誤った保存済み表示、ノード間混入、参照破損、無断上書き、
basePath破損、主要操作不能があればMergeを停止し、作品を保全して再現条件を報告する。
実機未実施のまま「iPhone検証済み」と記録しない。
