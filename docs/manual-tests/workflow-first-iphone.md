# Workflow First — 実機受入手順

2026-10-25 JST。現在はWFR-0/1抽出段階。実機結果は未取得。
WFR-2〜6を実装したreview buildで以下を実施する。未実装の手順を成功扱いにしない。

記録欄: 端末 / iOS / Safari / build SHA / rootまたはbasePath / 縦横 / 結果 /
再現条件 / スクリーンショット / 影響データの保全方法。

1. 旧StudioでPNG/JPEG追加、文字・図形・変数・複数ページ・クロップ・Undo/Redo。
   保存→再読込、テンプレート、PNG/JPEG/ページZIP、旧バックアップの別コピー復元。
   ゲスト/メール認証/復帰URL/logout後の作品保持。
2. 既存Workflowで空白/ノード上ピンチ、1→2→1指、pointercancel/lost capture後の復帰。
   25/100/200%でノード移動・タップ接続・詳細パネル44 CSS px以上の接続ボタン。
3. image-editを明示ボタンで開く。名前と保存状態、Workflowへ戻る入口を確認。
   A編集→適用して戻る→再開、Bの独立、連続開閉、複製後の独立、削除Undo。
   viewport/選択/フォーカス復帰、ノード位置と保存表示による画面移動なし。
4. 日本語IME変換中と不正数値では未確定表示。ソフトキーボード表示中の確定/戻る、
   safe-area、回転、ページ拡大、VoiceOverの一覧/設定/保存/戻る。文書座標が不変。
5. 作業版保存/適用版/出力更新必要/生成中/古い出力を区別。
   選択ページのみ生成、キャンセル/エラー再試行、上流未生成を元画像で代用しない。
   入力変更の維持/コピー差し替え/作り直しと差し替え前への復旧。
6. 制御可能な試験用profileで保存失敗・容量不足・2タブ競合を再現。
   エラー時は画面に残り、再読込/別コピー保存で両作品を保全。ブラウザ戻る、
   バックグラウンド/再開、再読込、保存中/未確定入力中の離脱を確認。
7. 新バックアップは別コピー復元、ID/参照/画像を確認。破損/容量不足で既存作品を保全。
   端末ダウンロードはFiles/Safari側も確認。ローカルDB保存と端末保存を区別。
8. 複数回開閉と生成取消後にKonva Stage/Canvas/Object URLの解放、メモリ推移を記録。
   rootと/axfluxoを別artifactで繰り返す。flag無効時も旧Studioを利用できる。

CI / Chromium mobile / Playwright WebKit / 実機Safariの結果欄を分ける。
旧データ消失、誤った保存済み表示、ノード間混入、参照破損、無断上書き、
basePath破損、主要操作不能があれば次段階を停止し、作品を保全して報告する。
