# Blomp Phase 2

## 構成と導入条件

Blompは原本と完成成果物の独立保存先。R2の素材、プレビュー、workerと既存データは既存経路に残る。端末エンコード、ダウンロード、途中データ、IndexedDB復旧は従来どおり。将来のproviderは共通のファイルメタデータに識別子を追加し、独立した操作経路を設ける。Drimeは未接続。

- `008_blomp_storage.sql` は追加マイグレーション。API起動時の適用処理はない。provider、location、所有者、ロール、固定object key、元名、形式、サイズ、SHA-256、versionと日時を記録。任意のproject/jobは所有者との複合外部キーを課す。端末だけのIDにサーバー上の関連先がない場合はnull。
- `/storage/blomp/overview`、`/files`、`/files/:id`、POSTの `resume`、`part`、`complete`、`pause`、`cancel`、`download` を独立Node APIで提供する。JWT、developer membership、トランザクションスコープのowner、強制RLS、4 KiB JSON上限、DB共有の利用者単位レート制限、no-storeを使用。署名返却の前後に認可を確認する。APIのリストはカタログのみ。Multipart照合では対象キーで絞り込んだ結果から完全一致のみ採用する。
- 8 MiB、直列パートは隔離環境用の暫定値。最終パートは端数を許可し、小容量も単一パートのMultipartを利用する。単独ブラウザPUTの署名は実装していない。XHRの進捗とブラウザ生成Content-Lengthを使用する。SHA-256計算は1 MiBのBlob slice。検証用GETはサーバーでストリーミングし、総量・ハッシュ一致後に公開する。通常の動画アップロード・ダウンロードのAPI中継はない。同期検証がHTTP期限や予算を超えた場合は公開を保留する。長時間の検証worker、プロバイダーが検証する完全オブジェクトのチェックサム、1 GB以上の公開可能性は今後の受入項目。
- 予約はlocationの1行を排他ロックし、全所有者で共有する。契約容量・確認時の使用量・安全余裕、ローカルの予約と完成加算を分離する。スナップショット有効期限は15分。データ不明・古い・外部使用により超過した場合は停止する。管理者だけが確認値を設定できる。外部消費、ゴミ箱、未完了の算入が確定しない間は書き込まない。管理者によるスナップショット更新時は、多重加算の防止に向け完成加算の内訳と観測値を照合し、安全に識別できなければ保持する。
- 検証GETは試行前に、PART/GETは署名返却前に該当する推定転送予算を消費する。中断しても自動で払い戻さない。これはAPI発行量の制限。署名URLの再利用や外部動作を含むプロバイダー課金の上限は、なお別途確認が必要。
- DBの操作lease、アップロードIDと状態を永続化し、ブラウザ再開時は元ファイル全体のSHA-256を再計算する。URLや追加JWTは永続化しない。パート一覧はプロバイダーを照合し、ETagを不透明な値としてCompleteに渡す。開始の応答喪失時は一意キーでMultipartを照合し、特定不能時は保留。完了の応答喪失時はHEADを優先する。期限切れ予約は、新しい署名を出さず、未完了オブジェクトの不在を確認したキャンセルの後でのみ解放。曖昧な状態やハッシュ不一致は保持し、完成扱いをしない。
- パート署名の有効期限は60秒。署名発行後のキャンセルには有効期限に加え転送猶予を設ける。完了はprovider側のUploadId終端と、ListPartsで得たETagの照合に依存する。発行済みURLの即時失効や一度だけの使用は保証しない。遅延転送・Abortの実際の意味は追加試験が必要。
- 開発者の素材画面で保存、再選択、検索・並べ替え、一覧、ダウンロードを操作できる。検索は取得済みページ内。画像ライブラリーは既存のサイズ制限と検証を通してBlompの画像を再利用する。All VersionsとFNF Showcaseの完成動画は共通Export Dockから明示保存でき、転送失敗後の再エンコードは不要。端末版All Versions/FNFは検証済みの対応素材を16 MiBまで受け取り、端末素材と同じ入力経路で作業できる。上限を超える素材はダウンロード後に端末のファイル選択を使う。既存のR2専用プレビュー契約への差し替えは行っていない。
- `BLOMP_ENABLED` は既定OFF。現行コードで本番起動時はアダプターを生成しない。隔離開発環境でもMultipart・ブラウザ転送・無料制約の各許可設定と、有効な容量スナップショットが必要。CORSの正確なoriginは `https://axsisaxsis0807.github.io`。Pages上の `/axfluxo/` はパス。

## 実サービス試験計画

各行は個別承認が必要。現在の作成・削除承認は0件。既存ファイルを列挙せず、承認済みの専用テストキーを各試験で一意に作る。データAPIは `https://storage.blomp.com`、容量は公式ダッシュボードか公式の読み取りAPIを使用する。下記はペイロード上限でヘッダー等を含まない。想定費用は確認済み無料枠内で0円。残量、転送量、料金挙動または必要な権限を確定できなければ開始しない。

| 試験 | 操作・上限・対象・必要権限 | 合格条件 |
| --- | --- | --- |
| CORS | 実originでOPTIONSとGET/HEAD、限定したPUTプレフライト。専用1件、合計4 KiB以内。作成・GET/HEAD/削除権限。 | Origin、各method、Content-Type、署名に必要なヘッダー、Range、Expose-Headersの ETag・Content-Length・Content-Rangeを個別に測定。 |
| 署名付きPUT | 専用1件、1024 B PUT・HEAD・GET、総量2 KiB以内。署名PUT・GET/HEAD・削除権限。 | 実際のブラウザヘッダーで受理し、HEADとSHA-256が一致。実装する場合は既存PART署名と別ゲート。 |
| Range | 専用1件、1024 B PUT＋256 B GET、誤って200になっても合計2 KiB以内。作成・GET/HEAD・削除権限。 | 206、正しいContent-Range、区間SHA一致。 |
| Multipart／PART／ListParts／Complete | 専用1キー・UploadId 1個。8 MiB＋1 KiBを署名PUT。最初のパートで中断し、ListParts照合後に残りを送信。合計18 MiB以内。開始・PART署名・ListParts・Complete・GET/HEAD・専用DELETE/abort権限。 | パート番号・サイズ・不透明なETag、完了応答喪失のHEAD照合、最終サイズとSHA一致。 |
| Abort | 専用1キー・UploadId 1個、パート1 KiB以内。開始・PART・ListParts・abort・HEAD権限。 | Abort後に同じアップロードを再開できず、HEADで完成物なし。遅延パートが残る場合は運用ゲートを閉じる。 |
| 期限切れ署名 | 専用1キー・UploadId 1個、期限後のPARTを1 KiB以内。開始・PART署名・ListParts・abort権限。 | 期限後に拒否、状態更新がない。新しい署名は再認可後に受理することを別ケースで確認。 |
| チェックサム | 専用2件以内、正常・不一致の各1024 Bと正常読み戻し、合計3 KiB以内。作成・HEAD/GET・専用DELETE権限。 | プロバイダーが対応するアルゴリズムで不一致を拒否し、返却値の意味を確認。 |
| 容量 | 公式アカウントの集計だけ読み取り。作成0件、素材転送0 B。アカウント容量表示の閲覧権限。 | 契約容量、実使用量、反映遅延、ゴミ箱・未完了・外部消費の算入、無料上限時の挙動を確認。 |
| iPhone Safari | 専用素材1件と端末生成の完成物1件、各最大8 MiBで開始。アップ・検証・ダウンロード合計48 MiB以内。開発者認証と前記Multipart権限。 | Filesから選択、転送中断、再読み込み、再選択、検証、取得、端末保存の継続を実機で確認。 |

各試験は想定外の転送、CORS/認証、サイズ・チェックサム不一致、料金・容量未確認またはcleanup不明で停止する。完了済みの専用キーのみを別承認のDELETEで処理しHEADで不在確認する。未完了は承認されたUploadIdだけabortして再照合する。曖昧な結果は追加通信せず、残存の可能性を報告する。1 GB、2 GB、5 GBはこの計画の上限外で、容量・転送枠・実機メモリの確認と各回の個別承認後に段階実行する。

CORS不可の場合は署名付きGETのトップレベル遷移を別に検証する。ブラウザからのアップロードは停止。端末保存を継続し、必要なら公式クライアント経由の手動転送を評価する。カタログ取り込みの自動化は別設計とする。

## ロールバック

APIをOFFにして署名の追加発行を止め、フロントの旧版を配信できる。DB行やオブジェクトを削除せず、既発行署名の有効期間と進行中セッションは照合対象に残す。今回のローカル差分を取り消す際はPhase 1のCLI修正・テスト・事前監査記録を残す。公開後のファイル削除は未実装。本番で別途設計する場合は所有者の明示操作、保持期間、固定location、削除前後の照合と監査記録が必要。
