# AxFluxo：曲間自動検出と中央固定編集

基点：最新main `f0ddeb6`（PR #23）。作業ブランチ：`feat/smart-track-boundaries`。mainへの直接変更・マージ・デプロイは行わない。

## 調査

- AGENTS.mdはリポジトリ／workspace内に存在しなかった。
- PR #21の復旧用IndexedDB、PR #22の4MiBバイナリチャンク保存、PR #23の実時刻トリムハンドルと保存表示の高さ固定を確認。GitHubのPR情報とローカル履歴・実装を確認した。
- `LocalVideoTool`が両ツールを所有し、`LocalTimeline`→共有`Timeline`へ素材時刻を渡す。クラウド版の`VideoPreview`も同じタイムラインを使う。今回の解析UIは既存ローカルファイル経路へ実装し、クラウド素材の取得は追加しない。
- `analyzeLocalWaveform`は1デコーダーで約4秒ずつ音声を展開する。表示用ピークは最大20,000binであり、曲間解析には解像度が不足するため、同じデコード経路の元PCMを使う。

## 実装

ピンチ開始時に中央時刻と2点の距離を固定し、全更新で同じ時刻を用いる。2点の中点は参照しない。ズーム後のDOM寸法反映に合わせてlayout effectでscrollLeftを設定し、ヘッドと表示座標も同期する。ピンチ終了時に中心時刻を公開する。繰り返し時には保持した時刻を使い、ブラウザーのピクセル丸めが蓄積することを避ける。既存の拡大／縮小ボタンの中心方式は維持する。

初回CIのWebKit試験で、`scrollLeft`が987.65424pxを987pxへ切り捨てることが判明した。実スクロールで表現できない小数部分をトラックのtranslateXで補い、中央ヘッドは補正を相殺して固定する。読み出しも「実スクロール＋補正」の同一座標に統一する。テストの許容値は変更せず、画面の位置は実スクロールと実際のCSS変換から測定し、時刻は6桁小数の期待値を維持する。Chromeでも整数setterを強制する回帰試験を追加した。選択枠にはinset shadowを使い、選択によるハンドル寸法やマーカー線の移動を防ぐ。

Version境界は44px幅の専用ボタンとして選択・ドラッグ・キーボード編集でき、選択中は枠を表示する。時刻を実時間で表示し、隣接境界と切り取り位置の内側へ制限する。画面外の境界を端へ偽装しない。元の数値入力は残す。「中央にVersion境界追加」を用意し、解析→候補へ移動→中央に境界追加の操作だけでも編集できる。候補の「境界として適用」は選択中の境界だけを変更する。FNFは既存rangeの開始／終了ハンドルへ同じ操作を適用し、Version管理を追加しない。

吸着は中央と候補から画面上で最も近い位置を選び、10 CSS pxで吸着、18pxを超える移動で解除する。全体の有効／無効切替とAltによる一時解除を用意する。ズームで距離の単位を変えない。吸着中は現在時刻と状態を表示する。

候補には区間背景・推奨位置の◆・一覧を表示する。中央／開始／終了／次の音声開始20ms前を選択でき、表示と適用・吸着に同じ推奨位置を使う。移動・前後2秒の試聴と停止・適用・削除・中央への手動候補追加・信頼度フィルターを用意する。除外範囲の候補へ移動すると編集表示へ切り替える。複数候補の一括適用は追加していない。

## 解析と対応範囲

- Worker内で20msごとに全チャンネルの二乗和、sample数、Peak、400Hz低域エネルギー、1次差分のエネルギーを累積する。逆位相チャンネルを平均して消す処理は行わない。RMS/dBFSと周波数分布の軽量な指標を得る。FFTや学習モデルは使っていない。
- dBFSの10／75パーセンタイルからノイズ床と活動レベルを推定し、-55〜-30dBFS内の適応閾値を用いる。3dBのヒステリシスと0.1秒の隙間統合で細かな切替を抑える。
- 0.2秒のギャップを検証対象に含めるため最短低音量は初期0.18秒とし、詳細設定から変更できる。候補の前後約3秒の音声活動を検査する。短い同一音の再開は中信頼度へ下げる。
- 完全ゼロは明確な無音根拠として扱う。微小ノイズ・残響は低音量根拠として高信頼度にはしない。短いブレイクも候補になり得るので無条件に確定しない。
- 無音がない場合、前後の帯域比と差分エネルギーの変化を比較する。ギャップレス／クロスフェードは低信頼度候補に限定する。似た音色の連続曲や滑らかなクロスフェードは検出できない場合がある。
- 候補は初期10秒の最小間隔で信頼度順に統合する。任意のVersion数は候補の優先・件数制限にのみ使い、不足分を生成しない。自動候補は最大2,000件。
- 解析済みの同一素材は保存結果を再利用し、再解析は明示操作とする。解析中の進捗とキャンセルを表示する。失敗・中断で既存候補や確定境界を消さない。
- RMSメーターは解析で得た現在位置の20ms値を表示する。表示を隠しても解析は変わらない。0dBFSはデジタル基準であり実スピーカー音量ではない。RMS配列は編集保存を膨らませないため永続化せず、リロード後のメーター表示には明示的な再解析が必要。

## 保存・メモリ

既存`Source.timeline`に任意項目として音源識別子、algorithm v1、検出設定、候補、削除履歴、選択境界、吸着設定、推奨位置を加える。編集途中の詳細設定も保存する。確定境界は従来の`Source.markers`またはFNFの`ranges`を使う。識別子はFileの名前・サイズ・最終更新日時・MIMEであり、プロジェクト内のsource IDに結び付く。全内容の暗号学的同一性判定ではない。素材変更・algorithm変更時には不一致の候補を適用しない。

既存の任意フィールド保存を使うためDBバージョンや既存素材の移行は不要。4MiBチャンク、チェックサム、書込リース、保存失敗時の画面保持、保存確認後の参照検査つき削除、動画エンコーダーを維持する。

約4秒分のPCMコピーをtransferし、Workerの応答後に次のチャンクへ進める。PCM解析モードでは表示用ピークの再計算と波形スナップショットの生成を省き、同じPCMをメインスレッドで再走査しない。通常の波形表示モードは維持する。全曲のPCMを保持しない。20ms特徴量のみ素材長に比例し、6時間を超える素材は理由と分割案内を表示する。Safariの非対応形式・チャンク時間精度異常・欠けたPCMは不完全な結果として公開しない。

10分／48kHz／ステレオの生成PCMを4秒ずつ処理したNode測定：7,299ms、30,000特徴量、候補10件、プロセス最大RSS 112MiB、JS heap 9→15MiB。これはファイルの圧縮デコード時間を含まず、同じ環境で他試験も動いている。iPhone性能・ブラウザWorkerだけのメモリ・6時間素材の実測値ではない。

Next.jsのTurbopackがWorker TSを未変換の静的素材としてコピーすることを本番成果物で発見した。`prebuild`/`predev`でesbuildにより自己完結JavaScriptへ変換し、同一originの`/workers/track-boundary-v1.js`から配信する。Pagesのbase pathを付ける。生成物だけをLintとgit対象から除外し、TS原本は検査する。

## 合成PCMの検証結果

| 音源                            | 結果                                 |
| ------------------------------- | ------------------------------------ |
| 1秒の完全無音を挟む2音色        | 区間と中央を高信頼度で検出           |
| 0.2秒の完全無音                 | 検出                                 |
| 指数減衰の残響                  | 低音量として検出、高信頼度にしない   |
| 微小ノイズ                      | 低音量として検出、高信頼度にしない   |
| 曲中0.2秒ブレイク／同じ音の再開 | 候補になり得るが高信頼度にしない     |
| ギャップレス音色切替            | 低信頼度で検出                       |
| 2秒クロスフェード               | 低信頼度で検出                       |
| 複数曲間／既知Version数         | 順序・間隔統合・件数優先を検証       |
| 音量差のある逆位相ステレオ      | 打ち消さず検出                       |
| 完全無音のみ                    | 候補なし                             |
| 無変化の連続音                  | 既知曲数を指定しても境界を捏造しない |

実楽曲の評価用データは提供されていない。精度の確率保証は行わない。曲中の長い無音など誤候補を完全に除去できないため、試聴と手動の確定を前提とする。

## iPhone実機確認手順と残存リスク

1. All Versionsへ権利のあるWAV／MP3／M4Aを読み込み、「曲間を自動検出」を押す。進捗中も片指の移動・縦スクロールができることを確認する。
2. 候補へ移動し、白いバーが中央、候補がその位置に一致することを確認する。「中央にVersion境界追加」または既存の境界を選ぶ。
3. 44pxの境界ボタンをドラッグする。候補と中央への吸着、引き離し、吸着OFF、隣接境界を追い越さないことを確認する。
4. 白いバーからずれた2点・斜めの2点でピンチを繰り返す。中央、0秒、終端、非常に高い倍率で、時刻とページ倍率が変わらないことを確認する。
5. 候補の前後を試聴する。短いブレイク・ギャップレス・残響について候補が正しいか耳で判断し、不要なら削除／手動追加する。
6. 自動保存済みを待ち、Safariを再読み込み／終了する。必要ならロックを解除し、最大約20秒の既存リース待ち後、確定境界・候補・削除履歴・詳細設定・選択対象が戻ることを確認する。
7. FNFでは既存rangeの開始／終了を選び、同じドラッグ・吸着・適用を確認する。通常再生は選択範囲内、編集時は元音源を確認できることを確認する。
8. 30〜60分の素材、容量不足、バックグラウンド移行、解析キャンセル、復帰後の再試行で、未保存編集や既存候補が消えないことを確認する。
9. 両ツールの動画を書き出し、Filesに保存して再生し、既存の保存確認後の削除を行う。他の未確認動画・新しい編集が残ることを確認する。
