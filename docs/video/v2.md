# V2: 非公開原本・folder・再開upload

2026-11-01 JST。開始時mainはAPI/fetchとも `367fb02570b4782aa5f51e892718fc473b376c59`、AGENTS.mdなし。V1 `934a2ab` を継承。未マージPR #8は固定画像入力/Studio復帰の変更で、新規cloud機能とは分離。既存LibraryRef、画像上限、4DB、V0文書、既存backup codecは変更しない。

## 境界と設定

静的 `/developer/library/`（basePath配下にも対応）から明示的にFileを選択する。既存画像の自動移行なし。cloud参照は独立したscopeで、旧画像LibraryRefを置き換えない。表示名はcontrol/bidi文字を除去したテキストとして表示し、内部keyは `originals/<owner UUID>/<session UUID>` のみ。

追加SQLは `server/db/migrations/002_cloud_library.sql`。適用はローカル試験DBのみ。本番migration・bucket作成・契約・deployはしない。管理者が将来、非公開R2 bucket（r2.dev/custom-domain公開なし）と専用資格情報を明示設定する必要がある。

| server変数                                          | 用途                                                  |
| --------------------------------------------------- | ----------------------------------------------------- |
| CLOUD_R2_ENDPOINT                                   | HTTPSのaccount.r2.cloudflarestorage.com。任意host不可 |
| CLOUD_R2_BUCKET                                     | 既存の非公開bucket                                    |
| CLOUD_R2_ACCESS_KEY_ID / CLOUD_R2_SECRET_ACCESS_KEY | serverだけ。NEXT_PUBLICへ渡さない                     |
| CLOUD_UPLOADS_ENABLED                               | 既定false。新規開始・新しいpart署名を停止できる       |

frontendはV1と同じNEXT_PUBLIC_VIDEO_API_ORIGIN。未設定なら通信しない。media_quotasのowner別limit_bytes未設定もfail closed。予約/確定bytesは管理者が設定した上限内で原子的に更新する。API roleには予算上限変更権限を与えない。

R2 bucket CORSは許可originを限定し、PUT/GET/HEAD、Content-MD5/Content-Type/Range、ExposeHeaders ETag/Content-Rangeを設定する。提示URLはpart 300秒、素材access 60秒。URLは再認可後に発行し、localStorage/DB/logへ保存しない。署名URLは有効期間内のcapabilityで、発行後のmembership失効を瞬時には反映できない。素材accessは固定versionで、ゴミ箱移動後も既存参照を保持する。

## データとAPI

private schemaにmedia_folders/assets/versions/derivatives、upload_sessions、media_quotasを追加。すべてowner必須・RLS、複合owner FK、RESTRICT。確定version/derivativeはimmutable triggerで保護し、削除APIなし。system_keyはowner内uniqueで、All Versions Video Maker/FNF Showcase Makerを二重作成しない。folder移動はowner単位advisory lockで直列化し、祖先を辿って循環・他owner・初期folder移動を拒否する。移動/改名/ゴミ箱/復元はmetadataのみ。

| endpoint（全操作V1 JWT/membership/owner検証）       | 機能                                                      |
| --------------------------------------------------- | --------------------------------------------------------- |
| GET/POST /cloud/folders                             | parentId/cursor/limit一覧、作成                           |
| POST /cloud/folders/:id/move                        | parentId変更                                              |
| GET /cloud/assets                                   | folderId/deleted/cursor/limit一覧                         |
| POST /cloud/assets/:id/rename, move, trash, restore | metadata変更                                              |
| POST /cloud/uploads                                 | Idempotency-Key必須で開始。V1と共通のowner/key unique台帳 |
| GET /cloud/uploads/:id                              | providerのListPartsと保存計画を照合した状態               |
| POST /cloud/uploads/:id/part                        | 固定size/SHA-256/MD5のpart署名                            |
| POST /cloud/uploads/:id/complete, abort             | 完了要求、未完了partsのみ中止                             |
| GET /cloud/versions/:id/access                      | 固定原本の短時間access                                    |

一覧はUUID昇順cursor。cursorはsnapshotではなくseek位置であり、途中追加分は再読込で確認する。原本hashのdedupはworkerが読んだ実bytes SHA-256だけで、owner内に限定。同名別内容は別asset。重複bytesは既存asset/versionを返すが、再転送候補object自体は自動削除せずsessionが保持するため、物理保存した候補bytesもquotaに計上する。ゴミ箱や既存metadataをdedupで勝手に戻さない。

## upload/probeの状態と復旧

16MiBから開始し、最大10,000partに収まるようMiB単位で動的拡張。5TiB/part 5GiB上限。browserは2並列、hashはFile.sliceで2MiBずつSHA-256/MD5を更新し、全File.arrayBufferを呼ばない。MD5はprovider part整合とContent-MD5署名のためだけに使用し、dedup/原本認証には使用しない。

開始前にowner、start key、size、期待SHA-256、session IDのヒントだけを新しいlocalStorage prefixへ保存。再読込でFileを復元しない。同じファイルを再選択して全hashとsizeを照合した後、各partのSHA-256/MD5とListPartsのsize/ETagを照合して再開する。名前/lastModifiedは同一性の根拠にしない。切断や背景化ではAbortControllerで止め、完了済みpartを残す。

creating → uploading → completing → verifying → ready/failed。外部処理にlease/CASを使う。create応答喪失は同keyとListMultipartUploads、complete応答喪失はHEADで復旧する。workerはcompletingも回復し、失敗で原本を上書きしない。multipart完了後にsizeを確認して予約を使用量へ移し、stream読取りSHA-256とffprobeが通った時だけasset/versionとV1の固定resource catalogueを同一transactionで公開する。偽MIME/hash不一致/破損/codec非対応は別code。失敗objectは非公開で保持し、想定外sizeは追加uploadを止めて管理者の照合を待つ。

ffprobeはlocal一時fileのみ、file/pipe以外のprotocolを禁止、最小環境（DB/R2秘密なし）、30秒timeout/出力上限で実行する。MP4/QuickTime/WebM、WAV/Ogg、PNG/JPEG/WebPと明示codec集合に限定。画像は従来の20MiB/24MP/8192px上限を維持する。一時fileだけをfinallyで除去し、R2確定objectを削除する処理はない。

`npm run build:probe --workspace axfluxo-video-server` / `npm run probe --workspace axfluxo-video-server`。ffmpeg/ffprobeを用意し、worker loginへaxfluxo_video_probeを付与する。API loginからこのroleを継承させない。workerはprivate queue発見後にもmembership/ownerを確認する。OSレベルのCPU/メモリー隔離、R2接続、資格情報配布は実運用環境で別途検証が必要。

未完了sessionの期限は7日。workerは未完了multipartだけAbortし、HEADで確定原本がないことを確認した後に予約を解放する。R2 lifecycleにも同じprefixのAbortIncompleteMultipartUploadのみを設定する方針（この作業では未適用）。Expiration/DeleteObject/確定原本の期限回収は設定しない。rollbackはCLOUD_UPLOADS_ENABLED=false。既発行part URLの期限を待ち、完了/状態確認/abort/probe/原本を保持する。

## 検証

合成素材はffmpeg lavfiの幾何学色からローカル生成し、network mediaを使わない。実PostgreSQLエンジンによる認可・folder循環・容量予約競合・重複complete/応答喪失・実SHA/probe・4種の検証失敗・同名別bytes・owner分離・原本保持を試験。17MiB超のFileを実API client経由で一部転送→切断→再選択し、未完了partだけ転送後にserverで元hash一致を確認する。

browser試験は背景化イベント、reloadによるFile喪失、別bytes拒否、同じFileの再選択を検証する。これは実機SafariのOS tab破棄/ITPを再現した証拠ではない。WebKitの配布先は環境の許可host制限で403（V1から継続）なので未実行。設定済みR2へのlive接続も行っていない。最終検証数はV3と合わせて記録する。
