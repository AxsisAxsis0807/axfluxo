# iPhone Safari試験D

## 開始条件

無料の隔離HTTPSプレビュー、テスト用ログイン、専用DBとBlomp保存先がそろってから始める。対象はこの変更を含むコミット。GitHub PagesのPRビルドは検証用成果物を作る。本番以外に外部公開するジョブは現行ワークフローにない。隔離URLは未発行。

最初は合成素材を使用する。試験素材ZIPには、0.7秒の `01-original.wav` と `02-alternate.wav`、カバー用の `cover.png` が入っている。各ツールの完成ファイルを512 KiB以内に収める。超えた場合はアップロードの操作をせず、端末内で区間を短くして再書き出しする。

## iPhoneでの手順

1. Safariで隔離URLを開き、テストアカウントでログインする。
2. **All Versions**で音声を2個選択する。異なる曲調の音声に「原曲」「Versão lenta」などの名前を付け、上下ボタンで順序を変更する。合成プレビューで名前と音の順を確認する。端末内で書き出して「ファイル」に保存し、先頭・曲間・末尾を再生する。
3. **FNF Showcase**で音声を1個選択する。譜面名を付け、短い開始・終了区間を指定する。プレビューを確認し、端末に書き出して再生する。黒背景、譜面名、音が指定区間に合っていることを確認する。
4. 隔離環境でクラウド試験の開始条件を確認できた場合だけ、完成動画ごとに「Blompに保存」を1回押す。「保存済み」の後に一覧から検証付きで1回ダウンロードし、iPhoneの「ファイル」から音と映像を再生する。

タブ移動や画面ロックによる中断の確認は、最初は保存前の端末書き出しまたはモック接続で行う。長い書き出し中はSafariを前面に保つ。

## 実Blompの試験範囲

- 保存先は隔離用のBlomp接続に固定する。サーバーが割り当てる新規の完成品キー2件だけを使用する。各キーは `axfluxo/05_完成品/` 以下でプロジェクト識別子と新しいUUIDを含む。テスト環境で発行されたファイルIDとキーの対応を管理者が照合する。
- ファイル本体は1件512 KiBまで。Multipartの1パート送信、サーバーでの検証読み戻し、ブラウザでの取得を2件行う場合は合計3 MiBまで。プロトコルのヘッダーやXMLは別に数える。
- 通常経路は1件あたりBlompへの9要求。開始、初回ListParts、Part PUT、未確定完成オブジェクトのHEAD、完了前ListParts、完了、完了後HEAD、検証GET、ダウンロードGETを含む。ブラウザのOPTIONSなども含め、計22要求を試験上限とする。隔離API側のリクエストも別に記録する。
- 現行UIにこの試験専用の要求数制限はない。厳格な上限が必要な実機試験では、隔離環境でBlomp通信を計測・遮断できることを開始前に確認する。
- 料金や制限の通知、認証エラー、CORSエラー、HTML応答、通信断、サイズまたはハッシュの不一致が出たらクラウド試験を停止する。元ファイルと端末出力を保持し、追加送信や削除を行わず、時刻と画面上の状態を記録する。署名URLと認証情報は記録しない。
