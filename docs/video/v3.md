## 入口と保存

`NEXT_PUBLIC_VIDEO_PREVIEW_ENABLED=true` と既存NEXT_PUBLIC_VIDEO_API_ORIGINを設定した開発用buildだけで入口を有効化する。既定OFF。CloudLibraryの検証済みvideoから固定versionを選択し、`/developer/preview/?version=<UUID>` へ進む。署名URL/credentialをページURLへ入れない。All Versionsの追加/trim/markerはV0のAllVersionsDocumentへ反映し、既存axfluxo-developer v1 documents storeにCAS付きで直列保存する。4つの旧DBやStudio rendererへ書き込まない。保存失敗/別tab競合は未保存を表示し編集状態を保持する。schema未知版は上書きしない。

FNFのrangeと譜面名はcomponent内の未送信状態だけ。独立rangeの重複を許可し、全体移動で長さを保つ。rangeだけの試聴も可能。V0の非overlap実行snapshotへ暗黙変換・保存・送信しない。将来の送信はrangeごとの独立jobまたはversionを明示した別実行契約で扱う必要がある。

## 時刻とUI

整数microseconds、frame変換はBigIntの有理数・half-up。1frame操作はV0の出力60fps基準。元素材の29.97/30/59.94/60fpsやVFRを60fpsへ強制変換する意味ではない。HH:MM:SS.uuuuuu/秒数を入力でき、長い時刻にDateや32bit演算を使わない。IME composition中は区間を確定せず、完了後にNFKC正規化して数値を検証する。

上部previewはAll Versions 16:9/FNF 9:16、下部timelineにplay/pause、seek、横scroll、pinch、trim handle、数値時刻、±1frame/±1秒。操作面は44px以上。touch-action:none/pointer captureはtimelineだけ。二本指になった時点でhandle draftを取消しpinchを優先し、pointercancel/lost captureで未確定trimを書かない。All Versionsは中央headを基準にzoom/scrollし、clipを半開区間で連結してmarkerを原本時刻から表示時刻へ写す。長いtimelineは8百万px以下のwindowへ原点を移し、巨大なCSS座標へ依存しない。

原本・検証済みversion・hashは不変。trimはdocumentのintervalだけを更新する。markerを区間外へ追い出す変更はV0のstrict検証で拒否する。FNFはrangeごとの端点を検証し、全体移動は境界でclampする。

HTMLVideoElement.currentTimeが主時計で、requestVideoFrameCallbackまたはtimeupdateで表示を更新する。wall-clock積分で再生時刻を作らない。playsinline/metadata preload、初回playはuser gesture。source切替では固定versionを再解決し、同一素材のcutも継続再生する。署名失効/再生エラーではJWT/membership/ownerを再検証してURLを再発行し、元位置へseekする。再認可後はpaused位置へ復帰し、再生開始は利用者のボタン操作を基本にする。背景化でpause/bookmarkし、foreground復帰で位置を戻す。readyState喪失時も最後の時刻を保持する。

波形は現在の素材のpeak metadataを遅延取得し、clipのtrim/連結座標へ写してwindow内だけ描画する。未取得の他素材を全量decodeしない。複数素材を大きく縮小表示した時、現在素材以外の波形は未取得となる。timelineのclip/markerと再生自体は全長を扱う。peak JSONも16MiBで受信を打ち切り、version/hashを検証する。proxy/元欠損/再生失敗/token失効/無効区間は別メッセージ。失敗で原本を変更しない。

## server派生物

追加SQL: `003_video_preview.sql`。全tableはprivate/RLS/owner FK/RESTRICT。API roleはqueue挿入/参照だけ、probe roleだけが生成結果を公開する。`POST /cloud/versions/:id/preview` はV1認可を毎回使い、検証済みvideo以外を拒否する。jobはowner/versionでunique。queued状態をcommitしてからPROXY_NOT_READYを返す。ready時にproxy/thumbnail/waveformの短時間URLとPTS mappingを返す。再認可時にも元素材の存在を確認する。

CLOUD_PREVIEW_ENABLED=true、および正のCLOUD_PREVIEW_UNITS_PER_SECONDとownerのV1 usage_budgetsが必要。未設定/不足では新規受付しない。job作成とcompute予約は同じtransaction。生成済みreadや同じversion再送では重複予約しない。生成後の実objectサイズをmedia quotaへ予約してからuploadし、公開と同時にstorage/computeを精算する。失敗・partial uploadの予約/候補は保守的に保持し、勝手な削除/解放はしない。運用上の再試行・精算は管理者が確認する。

```sh
npm run build:derivatives --workspace axfluxo-video-server
npm run derivatives --workspace axfluxo-video-server
```

workerはlease/heartbeat/CASでqueueを扱う。検証済み原本をstreamで一時fileへ取得し、size/SHA-256を再照合する。ffmpegで全長H.264/yuv420p/AAC MP4（faststart）を生成する。上限1280px、SAR/回転を正規化し、GPS等metadataをproxyへ複製しない。元PTSはcopyts/start_at_zeroとpassthrough、encoder/track timebase 1/1,000,000で保持し、元/出力の最初のpresentation timeとtimebaseをmappingに記録する。audio leadも全長に含める。生成物は別key `derivatives/<owner>/<version>/<attempt>/...`、条件付きPutのみ。originalsへのPutやDeleteを提供しない。

thumbnailと8kHz mono PCMから3解像度のmin/max peakを作る。PCMはstdoutを逐次処理し、全PCMを配列に保持しない。最細windowは最低100msで、長い素材では100,000bin以内へ調整し、10倍/100倍のlevelを同時集約する。source時刻からのaudio offsetも保存する。proxyに長さの切捨てはない。browserはRange対応のMP4をnative再生し、全量media ArrayBuffer/全量WebAudio decode/全frame cacheを要求しない。serverの全長transcode/peak生成は非同期で原本全体を逐次走査するため、完了前のproxyは利用できない。

ffmpeg/ffprobeはlocal file/pipe、秘密を含まない環境で実行する。OSのCPU/RAM/disk隔離はdeployment側の責務で、この作業では実環境の長時間性能は保証していない。派生物生成中断/codec build変更後のpartial結果、予算予約の回復は保守的にfailed/保持とし、原本は不変。

## rollbackと検証境界

NEXT_PUBLIC_VIDEO_PREVIEW_ENABLED=falseで再buildして入口をOFF。server新規生成も止める場合はCLOUD_PREVIEW_ENABLED=false。原本・派生物・job・予算・文書を残す。DB削除/downgrade/Studio置換なし。本番migration/deploy・契約・cloud作成は行わない。V2用の未完了multipartだけを回収するreview用ruleとCORSの雛形も `server/storage/policies/` に置く（未適用）。
