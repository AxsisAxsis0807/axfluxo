# 端末内動画編集・自動保存と復旧

対象: All Versions Video Maker / FNF Showcase Maker。基点は main `17944b3e07d32da23d49f64f04b0753fbaca73ee`（PR #20）。mainへの直接変更・マージ・本番デプロイは行わない。

## 調査した構造と原因

- `LocalVideoTool` が両ツールの素材・設定・描画クロージャーを所有していた。`LocalExport` → モジュール内の `ExportQueue` → `encodeLocal` が直列処理する構成。キューは画面移動後も残るが、リロード／タブ終了で素材参照・描画関数・完成Blobを失っていた。
- `Timeline` / `LocalTimeline` / `useWaveformDetail` とチャンク解析器を共有。bounds付きタイムラインでは余白とヘッドが中央固定方式でなく、最大ズームは8,000px/秒。無音のバーは除外済みだったが、Canvas中央の横線が無音にも残っていた。
- All Versionsは、Version境界で作られた区間数と名前の行数が厳密に一致する必要がある。1素材・境界なしに複数名を入力すると予約されない。境界やカバーの不足を事前に説明する表示がなかった。iPhone固有の単一原因を実機で特定した、とは扱わない。
- AudioContextの作成が同期的に失敗すると従来のtryより外へ例外が抜ける。非対応MIME・Canvas機能、画像ロードの停止、短時間の連打も扱う必要があった。
- PR #19/#20と未マージPR #8/#10/#11を確認。#20はChromeによるMP4試験環境の修正でありSafari成功の証拠ではない。`fix/local-export-preflight-feedback`はmainと分岐し、LocalVideoToolの14行の表示追加だけだった。入力中に`localIntervals`が例外を投げるため、そのまま取り込まず例外を捕捉する事前検証にした。
- リポジトリ内にAGENTS.mdは見つからなかった。既存CI・Pagesは型・Lint・単体・ビルド・動画ブラウザー・通常／サブパスE2Eを実行する。既存の認証・簡易ロック・クラウドレンダラー・他のIndexedDBは変更しない。

## 実装

### 書き出しと描画設定

`local-project.ts`へ既存の区間計算と描画関数生成を移動。描画内容・解像度・FNFの独立／重複rangeを維持する。設定とFileから同じジョブを再構築できるレシピを付与し、予約時の値を固定する。変更後の設定で既存ジョブを書き換えない。

`localProjectIssue`は入力途中の不正値でも画面描画を壊さず、日本語で境界・名前・カバー・範囲・スケール等を説明する。予約処理のtry内で実APIによるMIME／captureStream確認を行う。AudioContextのresumeはタップの同期処理中に開始し、準備はその後に行う。連打はrefでも防ぐ。画像ロードは30秒でタイムアウトする。

既存のMediaRecorder対応MP4／WebM方式を維持する。WebMをMP4という拡張子で保存しない。MP4を全Safariで保証する新しいサーバーフォールバックは構築していない。既存の別経路のクラウド処理は削除しない。

### 波形と操作

- 両ツールで左右に半画面の余白を置き、0秒と終端を中央へ置ける。余白は時刻／素材長に含めない。白いヘッドは画面中央に固定する。時刻目盛りは1/2/5系列で120 CSS px以上の間隔を取り、倍率の境目でラベルが重ならないようにする。
- ズームとピンチは中央時刻を維持する。最大192,000px/秒。手動移動後は再生を再開するまで自動追従を止める。縦のドラッグはレーンの縦スクロール、端ではページへ送り、横のドラッグと区別する。pointercancelで編集を確定しない。
- 横線と最小波形高さを作らない。IEEE浮動小数点の+0/-0をゼロとして除外し、epsilonによる音量判定はしない。微小な非ゼロ値もピークとして保持する。Canvasのサブピクセル描画なので、任意に小さい値が常に肉眼で見えることまでは保証しない。
- 1/10/100/1000倍の固定表示倍率を選べる。音声データ・再生音量は変更しない。大きい波形は表示領域で飽和する。
- 概要も圧縮音声の元sample rateでデコードする。詳細は可視区間を再解析し、元サンプル間隔より細かいデータを作らない。区間あたり20,000bin、Fileあたり4区間キャッシュ、直列デコードを維持。最大8ch/96kHz、短いチャンクのみ。元デコードサンプルが完全ゼロの場合だけ無表示。圧縮コーデック自体の残響・誤差をゼロへ丸めない。
- リモート波形v1の8kHz検証スキーマは維持し、ローカル波形の型だけ実sample rateを表現できるようにする。
- 開始／終了・Version境界は中央へ10 CSS px以内で吸着し、18pxを超えて引くと解除する。吸着時は中央の整数マイクロ秒値を採用する。境界の逆転・重複を拒否する。クリップ端のツマミは44pxの判定幅を保つ。トリムで除外したVersion境界は採用範囲から除く。

### 自動保存

既存DBにスキーマ変更を加えず、`axfluxo.local-video-recovery` v1を作成する。

| store    | 内容                                                                      |
| -------- | ------------------------------------------------------------------------- |
| projects | ツール種別＋安定project UUID別の最新編集設定。File／一時URLを直接持たない |
| assets   | project/source IDで共有するFile、カバー、job IDごとの完成Blob             |
| jobs     | 順番、状態、進捗、休憩設定、再構築レシピと出力参照                        |
| meta     | ツール別のactive projectと書き込みリース                                  |

設定変更時に保存し、画面が閉じた後も登録済み書き込みは直列で完了させる。新しいエディターの読込前に先行書込を待つ。素材・カバーを編集や進捗更新ごとに書き直さず、完成Blobも一度だけ書く。ストレージ見積もりは補助的に確認し、実トランザクションのquota/securityエラーを確実に表示する。途中の失敗ではプロジェクト／素材／ジョブをまとめてロールバックする。「保存済み」は該当書込が成功したときだけ表示する。

同じsource IDを複数の編集・予約が共有する。再選択した別File同士の全内容ハッシュによる重複排除ではない。Safariが保存領域を削除する場合や、素材・完成動画とブラウザー内部バッファの合計メモリには制約がある。元ファイルは保持する。

### 復旧・排他

ツールを開くと、そのツールのactive projectを読み、素材URLを作り直して設定・タイムライン・表示倍率・休憩設定を復元する。保存されたキューも復元し、完成Blobはそのまま再利用する。未完了ジョブのみ先頭から再作成する。途中フレームからの厳密な再開ではない。

共有キューを別タブが二重実行しないよう、書き込み／復旧は同一のIDBリースで排他する。リース20秒、編集中は5秒ごとに更新。全書込みとエンコードの開始／成果物公開前に所有を再確認する。旧タブは新所有者を上書きできない。クラッシュ直後はリース失効まで最大約20秒自動待機する。実行／準備状態のジョブは0%から復旧し、同じIDを再利用する。復旧を3回繰り返したジョブは自動ループを止め、通常の再試行に回す。

非表示・再ロックで停止する。前面へ戻ると中断したジョブを安全な単位から再実行する。SafariでAudioContextがsuspendedなら通常のキューに許可待ちを表示し、「音声処理を許可・キューを再開」の1操作を求める。保存に失敗した場合も通常のキューから保存を再試行できる。

保存済み素材が欠ける／レシピが不正な場合、保存データは消さずエラーを表示して復旧を止める。この破損状態を自動修復する機能は未実装。別タブが利用中の場合も編集を開かず、無断で上書きしない。既存の簡易ロック解除が必要な場合がある。下書き一覧・復旧一覧・復旧ボタンは追加しない。

### 保存確認と削除

保存リンクを押しただけで保存完了とは扱わない。Files／写真で実ファイルを確認したユーザーが、成果物ごとの「保存できました（一時データを削除）」を押し、確認ダイアログへ応答した後に対象ジョブを削除する。

同じプロジェクトの未保存成果物が残る場合は共有素材を保持する。全成果物の確認後、予約時の設定と最新編集設定が一致するプロジェクトだけを削除する。新しい編集があれば保持する。全projects／jobsの参照を確認し、参照されないassetsだけを同一トランザクションで削除する。他ツール・他project・未保存出力を一括で消さない。削除の保存が中断された場合は再読込で成果物が再表示され得るが、未確認の動画を失う方向には進めない。

## iPhoneで確認する操作・残存リスク

1. All Versionsで音声・カバーを選ぶ。2つのVersion名なら素材内に1つの境界を設定する。不足時は理由が表示され、正しい設定では予約・進捗が始まること。
2. 0秒／終端を中央へ置く。片指の横移動・縦移動・2本指ピンチ、中央時刻維持、端のツマミ、Version境界の吸着と解除、IME入力を確認する。
3. 無音PCMでは背景だけが残り、小音は表示倍率を上げて見えること。再生音量が変わらないこと。長い素材／48・96kHzでメモリと操作応答も確認する。
4. FNFで2本予約し、1本完成・もう1本未完了の時点でSafariを強制終了する。開き直し、必要なら既存ロック解除後、最大約20秒で編集と完成動画が戻り、未完了だけ先頭から再実行されること。音声の許可待ちは通常キューの1タップで進むこと。
5. AだけFilesへ保存・再生して保存確認する。Bは残ること。Bも確認した後に不要な素材だけが消え、別ツール／別project／新しい編集が残ること。
6. 容量不足・非対応形式・破損素材・バックグラウンド・画面ロック・複数タブで、無反応や「保存済み」の誤表示がないこと。

OS終了中の端末内エンコード継続、Safariによる保存領域消去からの復元、写真アプリへの実保存完了の自動検知、全iPhoneでのMP4対応、途中フレームからの厳密な復旧は保証しない。これらを実現済みとして表示しない。
