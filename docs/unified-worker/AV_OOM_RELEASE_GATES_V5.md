## 固定条件と512MBゲート

1920×1080/60fps、H.264/libx264、CRF18、preset medium、yuv420p/BT.709、文字alpha fade、Reference非線形fadeと時計、AAC 48kHz/320kbps、既存x264 threads2/lookahead等を維持する。CanvasリセットはPNG encode完了後のみの隔離候補で、品質を落として達成する案ではない。本番renderer/API/DB/flagsは変更しない。

十進 `512000000` と512MiB `536870912` を別集計する。CPU0.5、swap0、network none、新規隔離コンテナで5秒1タイトル・15秒3タイトル・30秒3タイトル・Reference・ずらした境界を最後のmux/検証まで完了し、各条件最低3回の独立成功、oom/oom_kill増分0が必要。ON条件で静止合成を実際に通らない試験はINVALID。15秒失敗時、その上限のより長い条件は停止する。memory.events.maxや上限張付きは成功しても圧迫として記載し、安全余裕がなければ研究PASSまで。

本番実用PASSにはさらに本番image・実Worker・実ストレージ・停止/復旧・長尺・複数ジョブ・CPU/ディスク/メモリ余裕の独立検証が必要。今回の診断image・30秒・少数反復は代用にならない。未解決ゲートがあれば本番HOLDを解除しない。

公開資料のMB/GB表記から実Blitzの `memory.max` の十進/二進値を確定したとはしない。Mediumの1GBは予約256MBと別の利用上限で、常に余裕を持って利用できる保証ではない。0.5CPUの合成結果もMedium予約0.1CPUでの安定性を保証しない。無料環境の自動サイズ変更は空きpool依存で、OOM回避策として当てにしない。10GBストレージ、バックアップの範囲、API速度、同時ジョブと保持ファイルの容量も別途確認が必要。

## v5の判定に直結する事実

十進512MBは5秒3回中2回完成・1回segment0 OOM、15秒3タイトルはsegment10 OOM。512MiBは5秒3回完成、15秒3タイトル1回完成したがpeak536,870,912 B・max増分34で上限張付き。512MiBの15秒最低3回、30秒/Reference/境界ずらしの受入反復は未実施で、そのprofileもHOLD。異なる3タイトルの受入をB2の1タイトルやB4の同一PNG再使用で代替しない。
